# DockStart v0.13.7：六个 AutoDock Vina 官方示例人工验收

这份清单用于手动确认 DockStart 能完成六类官方教程流程。它验证软件工作流、文件产物和协议语义，不把 docking score 当作真实结合或药效证据。

## 0. 测试前准备

1. 安装 **DockStart v0.13.7 Assisted**。Basic 不包含 RDKit/Meeko，不能完成原始 PDB、SDF、MOL 或 MOL2 的自动准备。
2. 从 AutoDock Vina 官方仓库下载完整 `example` 目录，不要只下载 GitHub 网页。
3. 打开 DockStart，点击右上角 **工具链**，确认：
   - AutoDock Vina：可用，建议 1.2.7；
   - Python、RDKit、Meeko：可用；
   - AutoGrid4：只有第 5、6 项需要。点击 **配置路径**，选择你自行安装的 `autogrid4.exe`，再点击 **重新检测**。
4. 每个示例建立独立项目目录，不复用前一个项目。
5. 固定随机种子只能提高复现性，不能保证不同计算机和线程数得到逐字节相同结果。`num_modes` 是最多输出数量；能量窗口内不足时，Vina 可以合法输出更少构象。

> AutoGrid4 是 GPL 外部工具，不包含在 DockStart 安装包中。DockStart 只检测和调用用户明确配置的可执行文件。

## 1. Basic docking：1IEP / imatinib / c-Abl

### 官方输入

- 受体：`example/basic_docking/data/1iep_receptorH.pdb`
- 配体：`example/basic_docking/data/1iep_ligand.sdf`

### 点击步骤

1. 在帮助页点击 **选择结构文件**。
2. 在 **本次任务** 选择 **全局对接**。
3. 在 **项目名称** 输入 `official_basic_1iep`。
4. 点击 **保存目录** 右侧的 **选择…**，选择测试项目的父目录。
5. 点击 **受体结构** 右侧的 **选择…**，选择 `1iep_receptorH.pdb`。
6. 点击 **选择一个或多个配体结构**，选择 `1iep_ligand.sdf`。
7. 点击 **创建项目并检查结构**。
8. 在“格式转换与 PDBQT 准备”页：
   - 在受体行点击 **转换受体为 PDBQT**；
   - 在配体行点击 **转换配体为 PDBQT**；
   - 两行都显示 **PDBQT 已就绪** 后，点击 **设置搜索范围**。
9. 在搜索范围中填写：

   | 参数 | 值 |
   |---|---:|
   | center_x | 15.190 |
   | center_y | 53.903 |
   | center_z | 16.917 |
   | size_x | 20 |
   | size_y | 20 |
   | size_z | 20 |

10. 点击 **保存搜索范围**，再点击 **进入 Vina 参数**。
11. 评分协议选 **Vina**；搜索彻底程度填 `32`，输出构象数量填 `9`，能量范围填 `3`。CPU 可留 `0`，随机种子可留空或固定为一个整数。
12. 点击 **保存 Vina 参数**，继续进入运行工作台。
13. 如果页面显示参数有修改，点击 **保存参数并重新检查**。
14. 运行前检查全部通过后，点击 **开始对接**。
15. 等待运行完成，点击 **查看本次结果**。

### 人工通过条件

- 运行状态为“已完成”；
- 结果表至少有 1 个 Mode；
- `runs/run_xxx/out.pdbqt`、`log.txt`、`scores.csv` 与 `metadata.json` 存在；
- 官方文档中 Vina/32 的最佳分数通常约为 `-13 kcal/mol`，但不要把精确数值作为唯一通过条件。

## 2. Flexible docking：1FPU / A:315

### 官方输入

- 受体：`example/flexible_docking/data/1fpu_receptorH.pdb`
- 配体：`example/flexible_docking/data/1iep_ligand.pdbqt`

官方教程把 c-Abl 的 Thr315 设为柔性残基，残基写法是 `A:315`。官方 Meeko 命令本身使用 `-a/--allow_bad_res`，因此出现“需确认将忽略的模板异常残基”不是 DockStart 私自放宽规则。

### 点击步骤

1. 新建项目，**本次任务** 选择 **全局对接**。
2. 项目名称输入 `official_flexible_1fpu`。
3. 受体选择 `1fpu_receptorH.pdb`，配体选择 `1iep_ligand.pdbqt`。
4. 点击 **创建项目并检查结构**。
5. 在格式转换页点击 **转换受体为 PDBQT**。
6. 如果出现普通受体的“不完整残基”清单：
   - 核对列表；
   - 勾选 **已检查并同意本次转换忽略这些残基**；
   - 点击 **确认并重新转换**。
7. 受体与配体都显示 **PDBQT 已就绪** 后，设置 Box：

   `center = (15.190, 53.903, 16.917)`，`size = (20, 20, 20)`。

8. 进入 **运行工作台**，确认当前是 **单配体任务**、**全局对接**、**Vina / Vinardo**。
9. 在 **受体柔性设置** 中点击 **有限柔性**。
10. 在 **柔性残基（最多 8 个）** 输入 `A:315`。
11. 点击 **检查选择**；页面应显示已确认 1 个有效残基。
12. 点击 **准备并启用**。第一次严格准备会显示黄色确认卡：**Meeko 将删除 27 个无法匹配模板的残基**。
13. 点击 **查看将被忽略的完整残基列表**，确认 `A:315` 不在被忽略列表中。
14. 勾选 **我已核对完整列表，同意本次忽略这些残基**。
15. 再次点击 **准备并启用**。
16. 顶部状态应切换为柔性受体已启用，并生成刚性部分和 `flex` 文件。展开清单后页面不应横向漂移。
17. 设置搜索彻底程度 `32`、输出构象数量 `9`、能量范围 `3`，点击 **保存参数并重新检查**。
18. 检查命令预览中同时存在刚性受体和 `--flex` 输入，然后点击 **开始对接**。

### 人工通过条件

- 柔性受体准备成功，且活动残基为 `A:315`；
- 运行命令包含 `--flex`；
- 运行完成并至少得到 1 个 Mode；
- 官方教程的 Vina 参考最佳分数接近 `-12 kcal/mol`，随机搜索可有差异；
- 当前 DockStart 只把这个步骤验收到 **Vina 柔性分支**。标准 AD4 maps 页面仍按刚性受体协议处理，不要把它当作官方 AD4 柔性分支。

## 3. Batch docking：多个配体逐个运行

官方 batch 语义是“一个受体、多个配体依次独立运行”，不是多个配体同时进入同一个评分体系。

### 建议测试输入

使用官方 `mulitple_ligands_docking/data` 中的原始结构，以同时验收 5X72 的残基和 alternate location 审查：

- 受体：`5x72_receptorH.pdb`
- 配体 1：`5x72_ligand_p59.sdf`
- 配体 2：`5x72_ligand_p69.sdf`

这两个配体应分别运行；不要把结果解释成官方“多配体共同对接”的联合评分。

### 点击步骤

1. 新建项目，选择 **全局对接**。
2. 项目名称输入 `official_batch_5x72`。
3. 受体选择 `5x72_receptorH.pdb`。
4. 点击 **选择一个或多个配体结构**，在同一个文件选择窗口中同时选择 `5x72_ligand_p59.sdf` 与 `5x72_ligand_p69.sdf`。
5. 点击 **创建项目并检查结构**。
6. 点击 **转换受体为 PDBQT**。严格准备会列出不完整残基 `A:29`，并要求为 `A:133 PHE` 选择 alternate location。
7. 在 `A:133 PHE` 下选择 `A`，勾选同意忽略清单中的 `A:29`，然后点击 **确认并重新转换**。两项审查必须在同一次重试中提交。
8. 依次准备两个 SDF 配体；三个输入都显示已就绪后，点击 **设置搜索范围并继续**。
9. 进入 **运行工作台**，点击 **串行批量筛选**。
10. Box 填写：

   `center = (-15, 15, 129)`，`size = (30, 24, 24)`。

11. 为快速人工验收，可设置搜索彻底程度 `8`、输出构象数量 `9`、能量范围 `3`、单任务 CPU `1`、失败重试 `0`、Top N `2`。
12. 点击 **保存参数并重新检查**。
13. 在 **配体队列与批量运行** 中确认可用项为 2，且两个文件都被选中。
14. 点击 **创建并开始对接**。
15. 等待两项都结束，点击 **生成批量筛选实验记录**；需要时可点击某一成功项查看 Mode 1。

### 人工通过条件

- 受体审查同时记录 `A:29` 的明确忽略和 `A:133=A` 的 alternate location 选择；
- 队列最终为 completed；
- 成功数为 2、失败数为 0；
- 每个配体有独立 attempt、配置、日志和输出；
- `screening_summary.csv`、Top N CSV 与 `screening_report.md` 可生成；
- 页面没有显示联合体系的单一总分。

## 4. Macrocycle docking：BACE_1

### 官方输入

- 受体：`example/docking_with_macrocycles/data/BACE_1_receptorH.pdb`
- 配体：`example/docking_with_macrocycles/data/BACE_1_ligand.mol2`

v0.13.7 已允许**单分子 MOL2**进入普通准备和受审查的大环准备；多分子/批量 MOL2 仍不开放。

### 点击步骤

1. 新建项目，选择 **全局对接**。
2. 项目名称输入 `official_macrocycle_bace1`。
3. 受体选择 `BACE_1_receptorH.pdb`，配体选择 `BACE_1_ligand.mol2`。
4. 点击 **创建项目并检查结构**。
5. 在格式转换页先完成受体 PDBQT 转换；若出现残基确认，按页面清单确认后重试。
6. 在常驻显示的 **大环配体准备** 中，把 **准备策略** 改为 **受审查的大环准备**。如果先尝试了普通转换，DockStart 检出大环后也会自动切到这里。
7. 保持最小环尺寸 `7`、最大断环数 `4`，点击 **分析大环候选**。
8. 确认页面第 2 步显示大环，并列出 7 个断环组合。
9. 选择带 **Meeko 默认** 标记的组合；参考方案的断环原子索引为 `[2, 3]`（界面按自身编号显示时，以 Meeko 默认徽标为准）。
10. 点击 **确认所选断环**。
11. 在第 3 步点击 **按确认方案转换配体**。
12. 第 4 步显示准备完成后，直接点击 **设置搜索范围并继续**；无需回到页面其他位置寻找入口。
13. 两个输入就绪后，设置 Box：

   `center = (30.103, 6.152, 15.584)`，`size = (20, 20, 20)`。

14. Vina 参数设置为：搜索彻底程度 `64`、输出构象数量 `20`、能量范围 `5`、CPU `1`、随机种子 `12345`。
15. 点击 **保存参数并重新检查**，再点击 **开始对接**。该任务明显比前几项慢，不要因界面暂时无结果而重复点击。

### 人工通过条件

- 审查页显示 7 个候选并完成明确确认；
- 准备后的 PDBQT 含大环协议证据和 2 个 glue 伪原子；
- 正式运行完成，得到 1–20 个连续 Mode；
- 结果报告包含大环候选/确认记录；
- 导出 SDF 后不应残留 `G` 伪原子。

## 5. Hydrated docking：1UW6

### 官方输入

- 受体：`example/hydrated_docking/data/1uw6_receptorH.pdb`
- 配体：`example/hydrated_docking/data/1uw6_ligand.sdf`
- 需要：外部 AutoGrid4。

### 点击步骤

1. 新建全局对接项目 `official_hydrated_1uw6`，导入上述 PDB 与 SDF。
2. 在格式转换页先把受体和配体转换为普通 PDBQT；保留项目中的原始 SDF 记录。
3. 设置 Box：

   `center = (83.640, 69.684, -10.124)`，`size = (15, 15, 15)`。

4. Vina 参数设为：搜索彻底程度 `32`、输出构象数量 `9`、能量范围 `3`、CPU `1`。若要复核固定结果，可用种子 `1952347903`。
5. 在左侧 **工作台** 区点击 **水合 AD4**。
6. 在步骤 1 点击 **准备水合配体**；完成后应记录 2 个 W 原子。
7. 在步骤 2 点击 **生成并校验 maps**；完成后应包含 `W.map`。
8. 在步骤 3 点击 **运行前检查**。
9. 检查通过后，在步骤 4 点击 **创建 run 并进入执行页**。
10. 在执行页点击开始按钮并等待 Vina 完成，然后返回 **水合 AD4** 页面。
11. 在步骤 5 点击 **加载水合结果**。

### 人工通过条件

- 水合配体准备、W map、运行前检查、run 和结果读取五步全部完成；
- Vina 输出 1–9 个 Mode 都是合法结果；本轮实跑得到 7 个，不应被误报为失败；
- 每个 raw pose 有水分子分类记录；
- `hydrated_retained.pdbqt`、`ligand_water_free.pdbqt`、scores 和水合 Markdown 报告存在；
- 水分子后处理不能改写 Vina 的 raw AD4 affinity。

## 6. AutoDock4 scoring：1IEP 标准 AD4 maps

### 官方输入

- 受体：`example/basic_docking/solution/1iep_receptor.pdbqt`
- 配体：`example/basic_docking/solution/1iep_ligand.pdbqt`
- 需要：外部 AutoGrid4。

### 点击步骤

1. 新建项目 `official_ad4_1iep`，选择 **全局对接**，导入上述两个 PDBQT。
2. 设置 Box：`center = (15.190, 53.903, 16.917)`，`size = (20, 20, 20)`。
3. 先把搜索彻底程度设为 `32`、输出构象数量设为 `9`、能量范围设为 `3`，点击 **保存参数并重新检查**。
4. 在运行工作台的 **评分协议 / Vina / AutoDock4 Maps** 卡片中点击 **AutoDock4（maps）**。
5. 在子协议中点击 **标准 AD4**，不要选择 AD4Zn beta。
6. 网格间距保持 `0.375 Å`；确认 X/Y/Z 点数均为合法偶数。受体与配体原子类型使用页面自动识别结果。
7. 点击 **生成并校验 maps**。
8. 状态变成 **AD4 maps 已就绪** 后，点击 **保存参数并重新检查**。
9. 检查命令预览包含 `--maps` 与 `--scoring ad4`，且不再把 `--receptor` 作为运行参数。
10. 点击 **开始对接**，完成后打开结果和 Markdown 报告。

### 人工通过条件

- AutoGrid4 生成完整 maps 并通过受体、配体类型和 Box 绑定检查；
- Vina 命令使用 `--maps ... --scoring ad4`；
- 至少得到 1 个 Mode；本轮固定输入实跑得到 9 个，最佳分数 `-14.75 kcal/mol`，与官方约 `-14.72` 的示例相符；
- 报告明确标记 AutoDock4 maps，且不与 Vina 分数直接比较。

## 出错时先看哪里

1. **柔性受体**：确认 `A:315` 未出现在“将被忽略”列表，勾选确认后必须再次点击 **准备并启用**。
2. **受体转换**：展开 **查看详情**，点击 **读取日志**；不要只依据顶部一句“失败”。
3. **宏环**：必须先完成候选分析和确认，才能点击配体转换。
4. **AD4 / 水合**：先检查工具链中的 AutoGrid4，再检查 Box、点数、配体原子类型与 maps 完整性。
5. **构象数量少于请求值**：只要 Mode 连续、分数有限且在能量窗口内，就不应按数量不足判失败。
6. **结果解释**：Docking score 仅供结构结合趋势参考，不能替代实验验证。
